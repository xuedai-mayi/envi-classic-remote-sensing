# 报告证据规范

`report-evidence.json` 是实验事实的来源，`report-evidence.md` 是便于报告 Skill 阅读的图文索引。

## 步骤字段

每个 `steps[]` 包含：

| 字段 | 含义 | 报告用途 |
|---|---|---|
| `ordinal` | 实际截图顺序 | 方法章节排序 |
| `stage_id` | 唯一阶段标识 | 和指导书检查表对账 |
| `caption` | 中文图片说明 | 优先作为图题 |
| `action_summary` | 实际执行的菜单或动作 | 方法文字 |
| `parameters` | 核、阈值、角度、波段、公式、输出设置等 | 参数表与复现实验 |
| `evidence_type` | tool/parameter/result/comparison/output | 防止用结果图冒充参数设置图 |
| `window_title` | 被截取的 ENVI 窗口 | 证明截图来自目标工具 |
| `screenshot_path` | 原始 PNG 绝对路径 | 报告插图 |
| `sha256` | 图片哈希 | 防止截图在报告前被替换 |
| `captured_at` | UTC 时间 | 审计 |
| `width`、`height` | 原图像素 | 清晰度和排版判断 |

## 截图质量

- 捕获完整工具窗口或结果窗口，重要按钮、参数和值不能被裁掉。
- 截图内不应包含与实验无关的应用或个人信息。
- 不对原始截图裁剪、涂抹、标注、拼接、增强或重绘，也不生成带标注的副本；需要强调时只用正文、图题或图片外的 Word 文本说明。
- 对照展示使用两个独立的原始图片对象，在 Word 页面中左右或上下排版；禁止生成合成图片。
- 同一 PNG 只能对应一个阶段；同一状态需要不同说明时，在正文中交叉引用，不复制成假步骤。
- 参数设置截图应在点击 OK/Apply 前捕获，结果截图应在计算和显示完成后捕获。

## 完整性判定

以下任一项发生时 `complete=false`：

- `required_stages` 中存在未截图阶段；
- 同一 `stage_id` 被重复使用；
- 必需阶段的实际顺序与指导书顺序不一致；
- PNG 不存在或 SHA-256 不一致；
- 截图总数低于门槛；
- 要求实验输出但没有登记文件。
- 老师数据、指导书或模板未登记，或登记后的文件哈希发生变化；
- 尚未冻结指导书步骤计划；
- 截图阶段不在冻结计划中、证据类型不符或缺少计划指定的参数键。

`report-evidence.json` 的 `inputs[]` 保存老师三类输入的路径、角色、大小和 SHA-256；`stage_plan` 保存截图前冻结的阶段。验收工具不得接受比 `stage_plan.minimum_screenshots` 更低的门槛。

报告 Skill 必须原样保留失败状态，不能将“未通过”改写为“已完成”。

## 建议的图题形式

```text
图 3-4  设置 h1 拉普拉斯卷积核及输出路径
图 3-5  h1 滤波结果与原始影像对比
图 3-6  Sobel h3、h4 结果的 Band Math 变量映射
```

图题描述截图中实际可见的状态，不使用“效果很好”“显著提升”等未验证结论。
