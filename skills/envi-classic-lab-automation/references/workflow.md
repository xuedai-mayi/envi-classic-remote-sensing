# 全自动遥感实验工作流

## 输入合同

开始前建立输入表：

| 类别 | 必需性 | 处理方式 |
|---|---:|---|
| 实验指导书 | 必需 | 提取步骤、参数、输出、分析问题和思考题 |
| 实验数据 | 必需 | 只读使用，先识别主影像、辅助波段、ROI、DEM 等角色 |
| 报告模板 | 必需 | 保留既有样式、固定字段、资源、页边距和页码；旧 `.doc` 先复制转换为 `.docx` |
| 学生信息 | 视模板 | 只使用用户提供的信息，不猜学号、姓名、班级或日期 |
| 参考报告 | 可选 | 候选冻结后才读取，只用于预建 rubric 的差距评估 |

老师的数据、指导书和模板缺少任一类时，输入门禁不通过。学生草稿只能作为历史证据迁移或调试材料，不能成为全自动流程的必需输入。

## 输入登记与计划冻结

1. `health_check`、`launch` 后调用 `register_inputs`，登记老师三类输入和 SHA-256。
2. 从指导书拆解全部步骤，区分 `tool`、`parameter`、`result`、`comparison`、`output` 五类证据。
3. 给参数阶段列出 `required_parameters`，例如 `kernel_size`、`iterations`、`data_type`、`formula`、`bands`、`output_name`。
4. 调用 `set_stage_plan` 一次性冻结计划。已有截图后不得建计划，计划建成后不得替换。
5. `finalize_evidence` 只读取冻结计划，调用方不能临时降低阶段数或输出要求。

## 步骤拆解规则

使用稳定、可排序的 ID，例如：

```text
01-open-input
02-select-band
03-open-convolution-tool
04-configure-kernel-h1
05-set-output-h1
06-view-result-h1
07-compare-h1-original
```

每个阶段只表达一个可验证状态。以下情形必须拆分：

- 打开工具与设置参数；
- 参数设置与点击执行后的结果；
- 多个核、角度、波段或算法分支；
- Band Math 公式输入与变量到波段的映射；
- 结果显示与结果统计。

## 执行循环

对每个阶段执行：

1. 说明预期窗口或结果；
2. 操作 ENVI；
3. 等待窗口或输出稳定；
4. 读取当前窗口，确认标题符合预期；
5. 截取真实界面；
6. 写入图题、操作摘要和参数；
7. 必要时检查输出文件是否出现；
8. 才进入下一阶段。

如果截图中参数尚未呈现、对话框被遮挡、结果未刷新或画面空白，该阶段不算完成。

## 报告交接包

交给 `remote-sensing-report` 的最小集合：

```text
template.docx 或 template.pdf
experiment-guide.pdf/docx
report-evidence.json
report-evidence.md
screenshots/*.png
实验输出文件及其哈希
用户提供的学生信息
```

其中 `report-evidence.json` 必须包含老师输入哈希和冻结步骤计划。

正文方法章节应以 `steps[].ordinal` 为唯一顺序源；图题首选 `steps[].caption`；参数来自 `steps[].parameters`，不得凭经验补写。报告插图必须再次计算哈希并与清单对账，不得按草稿内的图片位置猜测语义。

报告以转换后的老师模板为母版生成，真实使用 Heading 1/2/3 样式与 PAGE/TOC 字段。禁止在空白 `Document()` 上仅模仿字体和边距后声称“使用了模板”。

## 异常分支

- ENVI 未安装：停止并报告健康检查问题。
- 菜单未找到：列出包含关键词的菜单路径；不要改用屏幕绝对坐标点菜单。
- 窗口标题不匹配：列出受控进程窗口后重新定位。
- 对话框坐标漂移：重新截屏测量窗口内比例，先 `dry_run` 验证配方结构。
- 运算失败：保存错误对话框为诊断截图，但不能把它列为成功阶段。
- 输出已存在：使用新的运行目录或新文件名；不得覆盖原结果。
- 报告证据门禁失败：补做实验阶段，冻结计划不接受删减。
